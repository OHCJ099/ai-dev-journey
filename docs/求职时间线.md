| 阶段 | 频率 | 目标 |

**必须做的事**：建一个 `docs/投递记录.md`（表格：公司 / 岗位 / 投递日 / 状态 / 被拒原因 / 复盘）。**没有记录 = 没有复盘 = 重复踩同一个坑。**

**心态预期（提前植入，别到时候崩）**：11 月开始投的时候，你手上只有项目①，是全年最弱的时候 —— **前 30-50 份被拒是数据采集，不是失败**。这个阶段的目的是：① 摸清 JD 真实要求 ② 练习自我介绍 ③ 拿到面试反馈来校准学习重点。命中率低是预期的，不是对你能力的判决。

## 五、拿到实习怎么办（提前定好，免得到时候纠结）

**如果拿到日常实习（11 月-1 月期间）：**
- 学习节奏降到 **20 h/周**，周期拉回 26 周（内容不砍）
- 理由：**实习经历在简历上的权重高于「多一个项目」**。一边实习一边做项目，是最强的组合
- 注意：实习如果占满时间导致主线停摆，优先保主线 —— 一个"实习了半年但没作品"的人，不如"有实习 + 三个项目"的人

**如果拿到「实习转正」岗（2027 年 2 月后）：**
- 主线内容照走，但节奏放到最慢（15 h/周）
- 转正是 2027 届最现实的就业路径，**优先级最高**

**现状**：**未发生。** 选题 #91 与项目②同构，导师未强制技术栈 → **Plan B 不触发，下方 4 档保留备查即可。**

> 缓冲公式（10-05 校准点重算，不在文档里写死绝对值）：
> `缓冲(小时) = (剩余天数 ÷ 7 − 剩余内容 ÷ 周投入) × 周投入`
> 按 2026-09-19：剩余 135 天 = 19.3 周；19.3 × 28 = 540h；剩余内容 ≈ 512h（520 − 已完成 8h）→ 缓冲 ≈ **28h**。

**Plan B（按代价从小到大）**：
1. **毕设 = 项目③（Agent）改题** —— 代价最小，项目③ 本来就在排期内
2. **毕设 = 项目①（对话应用）加知识库外壳** —— 代价小，但要补检索部分
3. **换选题方向但保留 Python 栈**（如「文档智能处理工具」）—— 代价中，需要重新设计
4. **被迫用指定技术栈**（如 Java + openGauss）—— 代价最大：**此时应立即触发砍单阶梯**（砍项目③、MCP、Ollama），把节省的时间换给毕设，而不是加班硬扛

**判断原则**：毕设优先级高于项目③，低于项目①②。因为它同时是毕业门槛和简历素材，而项目③只是第三块筹码。
