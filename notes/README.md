# 笔记规范

## 三条原则

1. **笔记是压缩 + 关联，不是抄写。** 一条 ≤3 行，必须写清「用在哪」。抄代码、抄段落 = 没学。
2. **写不出笔记 = 那段没读懂** → 停下来，先用自己的话讲回一遍，再写。
3. **笔记只放这里，全部进 git。** 不另开 Obsidian / Notion / 纸质本 —— 多一个工具就多一个断点。

## 三类笔记（别混在一起）

| 文件 | 记什么 | 格式 |
|---|---|---|
| `notes/gotchas.md` | 报错与踩坑（**最值钱，直接就是面试素材**） | 报错原文（1-3 行）→ 原因一句话 → 解法一句话 |
| `notes/concepts.md` | 概念卡 | `概念 \| 我的一句话解释 \| 用在哪` |
| `notes/experiments.md` | 参数 / 方案的对比实验（RAG 阶段开始用） | 改了什么 → 前后效果 → 结论 |

已有的素材（先补这几条进 gotchas）：缩进=分支归属、`==` 与 `in`、f-string 漏 `f`、字面量写死、改完没存盘、PowerShell 里跑 bash 语法。

## 复习机制

每周日 10 分钟：只看笔记，把每条讲一遍。讲不出来的标 ✗，下周重看。**笔记不看第二遍 = 白记。**

## 怎么用第三方教程（例如 ai-agents-from-zero）

看教程分**两条轨道**，别混。

### 轨道 A：精读（项目驱动，占 95% 时间）

顺序必须是：

> 遇到问题 → 去教程里找那一节 → 读完立刻回来写代码 → 讲回 → 记一条笔记

章节 → 阶段映射（只在对应阶段打开）：

| 我们的阶段 | 打开它的哪部分 |
|---|---|
| W3-W8 API + Prompt | `01-1` 模型认识 / token / 上下文窗口、`01-3` 提示词工程 |
| W9-W16 RAG | `04-1` RAG 与知识库基础、`04-2 ~ 04-5` 项目（挑 1 个看思路，**不照抄**） |
| W17-W20 Agent | `03-1` LangChain、`03-2` LangGraph、`04-3` 项目思路 |
| W21 工程化 | `03-3` MCP 从原理到实战 |
| W22 部署 | `01-2` Ollama 本地部署与调用 |
| **跳过（不学）** | `02` 全部（Coze / Dify 低代码）、`05` 微调、`03-4` A2A（第 6 月后想拓展再看） |

### 轨道 B：泛读（概念兜底，每周日 30 分钟）

**想看随时可以看，但有边界** —— 压着"想看"的念头反而会偷偷乱看。

- 时间：每周日 30 分钟，写进日程（见 `ROADMAP.md` 四·二）。不占主线任务时间。
- 只读**认识型**章节：`01-1`（模型认识 / token / 上下文窗口 / 开源闭源 / 参数规模）、`01-4`（架构原理，只看概念、跳过公式）、`06-2`（当下热点）。
- 只做一件事：读完后写 3 行概念卡进 `notes/concepts.md`，**不写代码、不做项目**。
- 硬边界：**不许在轮到那个阶段之前读它的实操章节**（`03-1`/`03-2` 的 LangChain/LangGraph 代码、`04-x` 的项目源码）。两个原因：① 看不懂会挫败，容易得出"我不适合"的错误结论；② 看得"眼熟"（其实没懂）会让你在真正该动手的那一周跳过练习。**"眼熟"比"完全不会"危险。**

### 一句话判断标准

**读完要不要动手写代码？要 → 轨道 A（按需检索）。不要，只是想知道"世界上有这么个东西" → 轨道 B（周日 30 分钟泛读）。**

先看 `notes/概念地图.md` 确认这个概念排在哪一周；有位置的概念不用慌。

与官方文档冲突时，**以官方文档为准**（模型名、接口参数尤其如此）——二手讲解会过期。
