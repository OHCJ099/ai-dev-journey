## 3. 卡点

### 已修

1. **🔴 环境事故：Hermes 网页工具"卡死没反应"（学员报障，非 Hermes 的 bug）**
   - **现象**：学员报「每次你打开网页都会卡死没反应」→ 教练上一轮 `browser_navigate` 后整个回合中断
   - **取证**：`D:/Hermes/logs/errors.log` 实锤
     ```
     tools.url_safety: Blocked request to private/internal address: github.com -> 198.18.0.8
     tools.url_safety: Blocked request to private/internal address: raw.githubusercontent.com -> 198.18.0.91
     ```
   - **根因**：学员跑 **Clash Verge**（`clash-verge.exe` + `verge-mihomo.exe`，系统代理 `127.0.0.1:7897`）并开 **fake-IP 模式**（`fake-ip-range: 198.18.0.1/16`）。Clash 把所有域名解析成 `198.18.x.x` 假地址，真连接由代理接管；而 `198.18.0.0/15` 属保留网段 → **Hermes 的 SSRF 防护判定"内网地址，不许访问"→ 直接拦**。**本地终端 / git / uv 全正常**（不走 Hermes 网络防护层），所以只有网页类工具坏。
   - **修复**：`hermes config set security.fake_ip_ranges '["198.18.0.0/16", "2001:2::/48"]'`
     （IPv6 段一并加 —— 实测 Clash 同时发 `github.com -> 2001:2::8`，同属保留段）
   - **验证（独立新进程，绕过运行中进程缓存）**：`github.com` 放行 ✅ / `raw.githubusercontent.com` 放行 ✅ / **`127.0.0.1` 仍拦 ✅ / `169.254.169.254`（云元数据）仍拦 ✅ / `192.168.1.1` 仍拦 ✅** —— **防护未被削弱**
   - **⚠️ 需重启 Hermes 桌面端生效**：源码里 `_fake_ip_resolved` 是**进程级缓存**，读一次就定死，当前会话仍读旧值
