## 2. 讲回记录

| 讲了哪几行 | 结果 | 错在哪 |
|---|---|---|
| `try/except` vs `try/finally`（cli 改动） | 通过 | 学员原话「无论如何是否异常都会 finally，就算是 raise，原路回弹异常 finally 也会执行」——准确。补充：`finally` 在**离开 try 块的所有路径**（走完/`break`/`return`/抛异常）都执行 |
| 为什么 try 不从 `load_contacts` 开始包（Q1） | 通过（修正一处机制） | 学员答「文件坏了又强行保存了」——方向对；实测修正：`contacts` 从未被赋值 → `finally` 里 `save_contacts(..., contacts)` 抛 `UnboundLocalError`（**保存自己崩了**，不是「强行保存」），友好提示被顶掉；原文件反而没被覆盖 |
| 误提交 key 的处置顺序（A 题复验） | 通过 | 第一遍顺序错（吊销放最后）+ 混入 `git reset`；修正后学员自己复述：「先去平台删 key，然后 `git rm --cached .env` + `.gitignore` + commit 取消追踪，已提交就 `git revert` 抵消」。**核心步「吊销 + 换 key」两轮都答到** |
| Q1 system/user/assistant 三角色 | 通过（2 处补充） | 角色说对了；补充 ① `system` 是开发者给的设定、不是「给 assistant 看的」② **API 无记忆，多轮 = 客户端每次重发全部历史** |
| Q2 `stream=True` 差在哪 | 通过（1 处修正） | 「响应时间也更短」→ 修正：变短的是**首字到达时间**，总时长基本不变；流式返回的是逐块可迭代对象 |
| 请求/响应/错误分类/token 计费（四题） | 通过（2 处修正） | ① 响应结构贴全了，指出 `choices[0].message.content` + `usage` + 中转的 `cost_cny`；② 「为什么放 `else` 不放 `try`」答「不知道哪步有问题」——修正核心词是「**误抓**」：try 里多一行就多一分把自身 bug 伪装成接口错误的风险 |
| 单次费用核算（b 题） | 通过（学员自己抓出换算错误） | 第一版单价少打一个 0（算出 0.00094，实际 0.000094）；学员自查「就是我少打了一个 0」，改后算式与中转 `cost_cny` **逐位吻合** |
| 分页序号归属（W2 复验） | 通过 | 学员答「core 返回 10 条，cli 做分页，显示 123 123 123 1」——方向对；修正：core 必须返回**全局真实序号**（第 6 条标 6），cli 只决定显示哪几行；「每页都从 1 数」会让用户误读。**此项关闭** |
| 同步等待时 CPU 在干什么（async 讲回） | 通过（第一遍答错，第二遍准确） | 第一遍「CPU 在运行其他的异步线程」——「异步线程」不存在；修正后学员复述：「同步就是一个线程按顺序跑，等待网络时傻等……异步是这个线程遇到等待就把事放下，先去干程序里其他活，等回来了再接着跑」 |
| `try` 块作用域 / Pylance 误报（两处现场教学） | 通过 | `async with` 块外读块内变量有效（函数级作用域，缩进块不产生新作用域）；`import cli` 红线与 `u.prompt_tokens` 红线均为 Pylance 静态误报，**判断标准是实跑结果** |

**3 行「今天我学会了什么」**（学员原话，子教练仅修错别字）：
