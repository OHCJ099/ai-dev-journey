## 二、逐题细说

### 题 1 —— 通过，但有两个隐患

学员代码（原样）：

```python
max = 0
for a in docs:
    if a["blocks"] > max:
        file = {"source": a["source"]}
        max = a["blocks"]
    else:
        continue
print(file)
```

总指挥实跑三种输入：

```
正常数据    -> {'source': '请假制度.md'}                    ✅ 结果正确
全是 0 块   -> NameError: cannot access local variable 'file'
空列表      -> NameError: cannot access local variable 'file'
```

- **隐患 A（真缺陷）**：`max = 0` 作初始值，若所有 `blocks <= 0`，`if` 一次不成立 → `file` 从未赋值 → `print(file)` 崩。
  （与 `pyright` 的 `reportPossiblyUnboundVariable` 同一问题；`diagnosis` 原文件留在 `projects/` 会破全仓 0 errors 基线，故本证据改落 `logs/`。）
- **隐患 B（习惯）**：`max` 覆盖了内置函数名 `max()`。此处不影响结果，属命名习惯。
- **惯用写法（供后续自然引入，不专门开课）**：
  ```python
  top = max(docs, key=lambda d: d["blocks"])
  print(top["source"])
  ```

### 题 4 —— 半通过

学员答「都从后端的 collection 里取的」—— **这解释了「内容为什么一致」，不是「为什么是同一批」**。

关键（`api.py` 第 89~130 行）：**同一个 `hits` 变量被用了两次**——

```python
hits = query_lab.query_index(collection, req.question, req.k)  # 只检索一次
context = qa.build_context(index_hits)  # ① 拼进 prompt 给模型
return {"answer": reply, "sources": hits}  # ② 同一份 hits 原样返回前端
```

**为什么重要**：若检索两遍（一遍喂模型、一遍给前端），两边可能选出不同片段 → 答案引用了 `[3]` 但前端只列 `[1][2]` —— 这是 RAG 最常见的「引用对不上」缺陷。**当前实现无此缺陷，因为只检索一次。** 这句话面试会问。

### 题 5 —— 不会（如实记）

**B 快。** `in` 一个 **list** 从头逐个比 → `O(n)`；`in` 一个 **set** 走哈希表一次定位 → `O(1)`。
代价：set 需额外内存存哈希表，且**无顺序**。
