# 怎么用这套体系

本文件只做使用说明和导航。通用规则正文见 `.hermes.md`，验收流程见 `handbook/06-验收协议.md`，不在这里重复。

## 角色与一次循环

| 角色 | 职责 | 写入边界 |
|---|---|---|
| 总指挥（总教练） | 路线、派单、正式验收和交接 | 维护 07 及规则；追加正式验收结论 |
| 子教练 | 按当前任务教学、看代码与报错、记录执行证据 | 日报、进度记录、学习产出；权限细则见 `.hermes.md` 硬规则 10 |

1. **开工或继续**：从 `.hermes.md` 启动，读取 07 状态区、对应任务正文、执行日报及当前阶段要求。无需学员重新交代整套背景。
2. **执行与收工**：按 `logs/_模板-日报.md` 建表和逐项收工；字段只维护在模板，缺失如实记录。
3. **正式验收**：总指挥按 06 读取证据、核实对应版本、追加结论，再发布下一任务包。恢复中断按 06 的发布顺序处理。

进度台账是历史索引，不用物理最后一行判当前状态。同日可有多条执行/验收记录。外部维护记维护日志，不算学员学习，不代交总结或代做学习验收。

## 文件地图与权威位置

| 要查什么 | 去哪里 |
|---|---|
| 启动、角色权限、通用教学原则 | `.hermes.md` |
| 当前状态、挂账和当前派单 | `handbook/07-当前任务指令.md` |
| 本阶段特有的前置与教学重点 | `handbook/01`～`05` 对应阶段文件 |
| 正式验收、证据缺失及中断恢复 | `handbook/06-验收协议.md` |
| 日报固定字段与正式结论栏位 | `logs/_模板-日报.md`（唯一字段清单） |
| 内容顺序、阶段标准、容量与里程碑 | `ROADMAP.md` |
| 当天实际做了什么 | 对应的 `logs/<日期>-日报.md` |
| 过去的进度和决定 | `progress.md`，按日期/任务查证，不默认全文读 |
| 概念定位、笔记和实验材料怎么存 | `notes/概念地图.md`、`notes/README.md` |
| 求职计划与实际投递记录 | `docs/求职时间线.md`、`docs/投递记录.md` |
| 正式项目的主线代码与运行入口 | 各 `projects/*/README.md` |

同一个有效规则只维护一份正文，其他位置引用。记录可以增长，历史可以追溯；历史中的旧命令和状态不是当前指令。

## 何时找总指挥

- 需要正式验收、调整路线或重排任务。
- 当前任务与代码事实矛盾、教练跑偏，或卡点无法解决。
- 学习容量、精力或求职安排发生变化。

优先由教练查仓库与相关会话，学员不用重打已经答过的内容。权限与教学原则冲突时回查权威文件，不靠旧印象自行改派。
