## 我已具备（不要重复教）
Python 分层写代码、大模型 API（流式 / 多轮 / 错误处理）、Prompt 基础、FastAPI 最小接口 + 单页前端。

## 本阶段目标
独立搭出一套**真正能用**的知识库问答系统，并且能讲清每一步的取舍理由（**面试就考这个**）。

## 本阶段交付物（项目②，放 `projects/rag-kb/`）
1. 文档加载 + 切分（chunk 策略可解释，切分结果能人工检查）；**语料 = 企业制度文档（毕设 #91 直接复用）**
2. Embedding + 向量库（先用 Chroma）：能对文档提问并召回片段
3. 拼上下文 + **带引用来源**的回答 + 资料里没有就拒答
4. 检索优化：多路召回 / 重排 / 查询改写，至少做两种并对比
5. **评估集**：20 条问题 → 期望答案，算出命中率 / 正确率，**必须有数字**，写清改了什么让它涨了
6. FastAPI + 网页界面：能上传文档、能提问、能看引用
7. 部署（局域网 / 内网穿透 / 云主机任选）+ 演示录屏 + README + 架构图

## 技术选型（默认，别乱换）
- 向量库：**Chroma**（入门）。**不用 openGauss** —— 我已明确判断并拒绝（华为生态、地域窄、与就业方向不符），**不要再提**，也不要写进 README 当加分项
- 框架：**优先手写一遍完整流程**（自己写切分 → 向量化 → 检索 → 拼 prompt），跑通后再用 LangChain / LangGraph 重写一遍做对比 —— 这样面试才讲得出「框架帮我做了什么」
- 文档：https://docs.trychroma.com/

## 本阶段专属规则
- **每个功能都要跑对比实验**：改一个参数（chunk=200/500/1000、top_k=3/5）就记录效果差异，写进 `projects/rag-kb/experiments.md`。**没有对比，这个阶段就白学。**
- **颗粒度平移（关键）**：Chroma / LangChain 这类框架的样板代码**主动给我标准骨架**，不要求逐行手写、不抠底层实现。讲回重心 = **切分与检索的取舍理由、数据在索引与检索之间怎么流动、评估数字、失败案例怎么兜底**
