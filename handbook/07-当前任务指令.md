## 第 2 件：参数化 `argparse`（约 1 小时）

**目标**：`uv run python week04/chat_cli/main.py --system "你是个程序员"` —— 启动时就能定角色，不用进去再敲 `/system`。

### 先讲①：`argparse` 是什么（讲完立刻给样例，别只讲不给）

**先讲这个（不先讲就出题 = 违反硬规则 9，09-22 已因此让学员卡 40 分钟）**：

`argparse` 是**标准库**（不用装），管的是「**命令行里跟在文件名后面的那些东西**」。你现在跑程序是：

```
uv run python week04/chat_cli/main.py
```

加 `--system "你是个程序员"` 之后，程序内部就能读到 `"你是个程序员"` 这个字符串。

**最小可抄样例（直接给他抄，让他先跑通这个 8 行的独立脚本再改 main.py）**：

```python
import argparse

parser = argparse.ArgumentParser(description="聊天命令行")   # ① 建一个「参数解析器」
parser.add_argument(                                        # ② 声明一个参数：叫 --system
    "--system",
    default="你是一个简洁的中文助手，回答不超过两句话",       # ③ 命令行没给时用这个
    help="开场时用的 system 提示词",
)
args = parser.parse_args()                                  # ④ 读命令行，解析结果放进 args
print(args.system)                                          # ⑤ 取值：args.system（-- 变 _）
```

**五个新名字（讲清每一个）**：

| 名字 | 干什么 |
|---|---|
| `ArgumentParser()` | 建一个「参数解析器」对象 |
| `add_argument("--system", ...)` | **声明**一个参数。`--system` 是命令行里要敲的名字 |
| `default=...` | **命令行没给时用什么**。这一条是本件的关键：不加它，不传 `--system` 就会报错 |
| `parse_args()` | 真正去读命令行，结果装进 `args` |
| `args.system` | 取值。注意：`--system` 里的横线会变成下划线（`args.system`，不是 `args.--system`） |

**让他先单独跑这个脚本两遍**（带 `--system` 和不带），看到 `print` 出不同结果，再动 `main.py`。

### 然后：把 `--system` 接进 `main.py`

**要改的就一处**：`SYSTEM_PROMPT` 那个常量，改成从 `args.system` 取。

**验收**：

1. `uv run python week04/chat_cli/main.py` → 用默认角色（行为和现在完全一样）
2. `uv run python week04/chat_cli/main.py --system "你是只会说文言文的夫子"` → 开场问「你是谁」立刻是文言文

## 第 3 件：日志（约 40 分钟）

**目标**：每轮往 `week04/chat_cli/chat.log` 追加一行（时间 + 谁说的 + 内容前 20 字）。

### 先讲②：`logging` 是什么

**先讲这个**（同第 2 件，不许让他推导）：

`print` 是「说给人看的」，`logging` 是「**记下来事后查的**」。服务在半夜挂了，你不可能是坐在屏幕前看着 `print` 的 —— 日志是唯一能还原现场的东西。**项目①上线后、W21 部署时，排查问题全靠它。**

**最小可抄样例**：

```python
import logging
from pathlib import Path

logging.basicConfig(                                    # ① 全局配置，整个程序只在开头做一次
    filename=Path(__file__).parent / "chat.log",        # ② 写到哪个文件（复用 W2 的 Path 写法）
    level=logging.INFO,                                 # ③ 记 INFO 及以上级别
    format="%(asctime)s %(levelname)s %(message)s",     # ④ 每行的格式：时间 + 级别 + 内容
    encoding="utf-8",                                   # ⑤ 中文要写这个，否则可能乱码
)

logging.info("用户说：%s", "你好")                       # ⑥ 记一条。%s 后面跟要填进去的值
```

**新名字**：

| 名字 | 干什么 |
|---|---|
| `basicConfig(...)` | 一次性配置：写哪个文件、什么格式、什么级别 |
| `filename=` / `level=` / `format=` / `encoding=` | 上面四个 |
| `logging.info(...)` | 记一条 INFO 日志。**`%s` + 逗号后面跟值**（不是 f-string —— 这是 `logging` 的标准写法，先照抄） |

**要做的**：在 `main.py` 里记两种行 —— 用户输入（前 20 字）和 AI 回复（前 20 字）。

**提示**：取前 20 字用**切片**（W1 学过）。

**验收**：

1. 跑 3 轮后 `chat.log` 存在，里面有 6 行左右（3 条用户 + 3 条 AI）
2. 每行**开头有时间**，**中文不乱码**
3. 用记事本或 `read_file` 打开看 —— **文件能被正常打开**（乱码就说明 `encoding` 没写对）

**讲回题（必须答）**：日志和 `print` 差在哪？**答到「`print` 看完就没了（窗口一关就没了）、日志写进文件能事后查」才算过。**
