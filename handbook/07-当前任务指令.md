### 第 3 件：修两个真 bug + 加测试（约 80 分钟，**本轮最重要**）

#### 3a. `cli.py`：非 `quit` 退出就丢数据（30 分钟）

**现在的问题**（总指挥实跑复现）：

```bash
printf 'add 测试 111\nlist\n' | uv run python week01/contacts/cli.py
```

→ 你会看到 `EOFError: EOF when reading a line` 的 traceback，**而且 `add` 的人根本没写进 `contacts.json`**。用户 `add` 完 10 个人直接关窗口 → 全丢。

**根因**：`save_contacts` 只在 `quit` 分支被调用；`input()` 遇到输入结束会抛 `EOFError`。

**要求**：让「意外退出」也存盘、不崩。两个方向（自己选实现）：
- `try / finally` 把主循环包起来，`finally` 里存盘
- `except EOFError:` 捕获后存盘 + 友好提示

**验收**（实跑给我看输出）：
- 上面那条命令 → **不崩**，且 `grep 测试 week01/contacts.json` 有结果
- 正常 `quit` 仍然工作、数据仍然存

#### 3b. `storage.py`：结构校验（30 分钟）

**问题**（总指挥实跑复现）：`contacts.json` 是**合法 JSON 但结构不对**时程序会崩：

```
null         -> CRASH: 'NoneType' object has no attribute 'append'
{}           -> CRASH: 'dict' object has no attribute 'append'
"abc"        -> CRASH: 'str' object has no attribute 'append'
123          -> CRASH: 'int' object has no attribute 'append'
[[1,2]]      -> 不崩，但列表里混进 list（脏数据）
[{"name":1}] -> 不崩，但 name 是 int（脏数据）
```

**根因一句话**：`json.loads` 只保证「能解析成 JSON」，不保证「是 `list[dict[str, str]]`」。**类型注解是给人看的，运行时不管。**

**做法**：`load_contacts` 读完加一次结构检查 —— 不是 `list` 就抛；是 `list` 但元素不是 `dict`、或缺 `name`/`phone` 也抛。
**注意**：校验失败**绝不能返回空列表** —— 返回 `[]` 后用户一敲 `quit`，`save_contacts` 就把 `[]` 写回去，真实数据被静默覆盖（这个道理你 09-18 已经答对过）。
