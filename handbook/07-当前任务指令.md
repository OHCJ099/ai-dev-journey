## 第 2 件：结构化输出 JSON（约 1h）

**目标**：让模型**稳定输出 JSON**，程序把它解析成 Python 对象。

### 先讲①：`json.loads` 是什么（讲完给样例）

**他学过 `json.dumps`（W4，Python 对象 → 字符串）和 `json.load`（W2，文件 → 对象）。`json.loads` 是第三种：字符串 → Python 对象。**

```python
import json

text = '{"name": "林小宁", "skills": ["Python", "RAG"]}'
data = json.loads(text)          # ① 字符串 → 字典
print(data["name"])              # 林小宁
print(data["skills"][0])         # Python
```

| 名字 | 从哪 → 到哪 |
|---|---|
| `json.dumps(obj)` | Python 对象 → **字符串**（W4 用过，`/save`） |
| `json.load(f)` | **文件** → Python 对象（W2 用过，`storage.py`） |
| **`json.loads(text)`** | **字符串** → Python 对象（本件新学） |

**记法**：`loads` 末尾的 **s = string**。

### 要做的事

1. 让模型输出 JSON（prompt 里写清字段名，例：「输出 JSON，字段为 `name` / `skills` / `level`，不要任何多余文字」）
2. 用 `json.loads` 解析
3. **`try/except` 兜底**：模型偶尔多嘴（JSON 前后加解释），这时 `json.loads` 会抛 `json.JSONDecodeError` → **不能崩，要打印原始文本**（他在 W1 学过 `try/except`）

**破坏性测试（他跑，输出贴回来）**：
- 故意不给格式要求 → 看模型输出什么、`json.loads` 会不会崩
- 让模型「先解释再输出 JSON」→ 看兜底是否生效

**讲回题（必须答）**：
- 为什么不能直接 `eval()` 或用字符串切？（方向：不可靠、不安全）
- `json.dumps` 和 `json.loads` 方向相反，哪次用过前者？

## 第 3 件：温度实验（约 50 分钟）

### 先讲②：`temperature` 是什么（讲完给样例）

**`temperature` = 模型的「随机程度」旋钮，取值大概 0~2。**

- **调低（0~0.3）**：每次都挑最可能的词 → **稳、可重复**
- **调高（1.2+）**：给低可能性的词更多机会 → **活、有变化、也更容易胡说**
- 默认一般 1.0

**用法（就多传一个参数）**：

```python
resp = client.chat.completions.create(
    model=MODEL,
    messages=[...],
    temperature=0.2,        # ① 新加的这一行
    extra_body={"thinking": {"type": "disabled"}},
)
```

**`top_p`** 是另一个同类旋钮（按累计概率截断候选词）。**实践中调一个就行，别同时调** —— 一起调会互相打架、效果难解释。

### 要做的事

**同一个 prompt（例「给一家做宠物粮的店起 5 个名字」）跑 3 个温度**：`0.2` / `1.0` / `1.5`，**每个温度跑 3 次**，看：
- 同一温度下 3 次结果**像不像**
- 不同温度之间**差在哪**

**讲回题（必须答）**：
- 什么任务该调低、什么该调高？**各举一个具体例子**（不能只说「稳定的调低」）
- 温度调到 2.0 会发生什么？（方向：开始胡说、不遵守格式）
- **温度能改变模型的知识吗？**（方向：**不能** —— 它只影响选词，不知道的还是不知道。**这条面试常考**）
