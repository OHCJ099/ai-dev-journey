### 第 4 件：修两个真 bug + 加测试（60 分钟，**本轮最重要**）

#### 4a. `storage.py` 加结构校验（30 分钟）

**背景（外部审计实跑发现的真 bug，总指挥已复现）**：`contacts.json` 是合法 JSON 但结构不对时，程序会崩：

```
null        -> NoneType  | CRASH: 'NoneType' object has no attribute 'append'
{}          -> dict      | CRASH: 'dict' object has no attribute 'append'
"abc"       -> str       | CRASH: 'str' object has no attribute 'append'
123         -> int       | CRASH: 'int' object has no attribute 'append'
[[1,2]]     -> list      | 不崩，但列表里混进 list（脏数据）
[{"name":1}] -> list     | 不崩，但 name 是 int（脏数据）
```

**根因一句话**：`json.loads` 只保证「能解析成 JSON」，不保证「是 `list[dict[str, str]]`」。**类型注解是给人看的，运行时不管。**

**做法**：`load_contacts` 读完加一次结构检查 —— 不是 `list` 就抛（复用 `json.JSONDecodeError` 或自定义异常，你选）；是 `list` 但元素不是 `dict`、或缺 `name`/`phone` 也抛。
**注意**：校验失败**绝不能返回空列表** —— 返回 `[]` 后用户一敲 `quit`，`save_contacts` 就把 `[]` 写回去，真实数据被静默覆盖（这个道理你 09-18 答对过）。

#### 4b. `cli.py` 修「非 `quit` 退出就丢数据」（20 分钟）

现在只有 `quit` 分支存盘。用户 `add` 完 10 个人直接关窗口 → 全丢；输入结束（EOF）还会直接崩。

**要求**：让「意外退出」也存盘、不崩。两个提示（自己选实现）：
- 用 `try / finally` 把主循环包起来，`finally` 里存盘
- 或 `except EOFError:` 捕获后存盘 + 友好退出

**验收**（实跑给我看输出）：
- `printf 'add 测试 111\nlist\n' | uv run python week01/contacts/cli.py` → **不崩**，且 `contacts.json` 里有「测试」
- 正常 `quit` 仍然工作
- 讲回：为什么 `finally` 能保证存盘？和 `quit` 分支里直接存盘有什么不同？
