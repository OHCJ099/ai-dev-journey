## 二十二、下一轮（10-20）：**W18 手写 ReAct 多步循环**

> **`ROADMAP` W18 = 手写 ReAct 多步循环、错误重试。** 验收标准：**能讲清循环终止条件、防止死循环**。LangGraph 在 W19，**本轮不引入任何框架**。

### 第 0 件（**10 分钟**）：W17 收尾两笔小债

1. **删 `.env` 残留键 `LOCAL_API_KEY_`** —— 代码与文档零引用，疑为本地反代残留。**只删这一行，不要动 `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY`**。删完跑 `Get-Content .env` 确认只剩 2 个键名。
2. **`projects/agent-lab/README.md`** —— 5 分钟版本即可：① 3 个工具各自的输入/输出契约（一张表）；② 怎么跑（`uv run python tools_demo.py`）；③ 一句话说明「这是 W17 最小版，W18 会换成 ReAct 循环」。

### 第 1 件（**约 40 分钟**）：把 `if/elif` 分发改成 `dict` 查表

**为什么先做这个**：W18 的循环里每一步都要「按名字找工具」，`if/elif` 链会让循环体里全是分发代码，看不出循环本身。**这是循环的前置，不是额外作业。**

**先讲后做**（硬规则 9）：`dict` 存函数、`TOOLS_BY_NAME[name]` 取、`.get()` 兜底未知工具 —— **给 ≤25 行可跑样例，讲完再让他改**。

**验收**：`tools_demo.py` 里 `if/elif` 分发**零命中**；3 个工具仍全部可调；未知工具名走 `.get()` 兜底而不是 `KeyError`。

### 第 2 件（**约 1.5–2h，主件**）：手写 ReAct 循环

**先讲后做**：ReAct 的四步（**Thought → Action → Observation → 再 Thought**）、**为什么必须有最大步数**、**什么时候该停**。给 ≤25 行骨架，**不给完整答案**。

**必须做到的 4 条**（缺一条不算完成）：

1. **`while` 循环 + 最大步数**（如 `MAX_STEPS = 8`），超限要有明确退出语，不能静默停
2. **终止条件**：`finish_reason == "stop"` 就 `break`，不能靠数步数停
3. **多步任务**：至少一个任务**需要连续调 2 次以上工具**才能答完（如「算 12×8，再把结果减去 6」→ 先 `multiply` 再 `subtract`）
4. **错误重试**：工具抛异常或返回 `{"error": ...}` 时，**把错误当 observation 喂回模型**让它自己改，**不让程序崩**

**不做**：多轮对话记忆、接 RAG、LangGraph、async。**这些是 W19/W20 的。**

**验收**：① 多步任务实跑跑通并打印每一步的 Thought/Action/Observation；② 故意喂一个会失败的工具调用（如除零、传错参数），程序**不崩**且模型拿到错误后有反应；③ 能讲清「为什么不能只靠 `finish_reason` 退出、为什么还要有 `MAX_STEPS`」；④ 静态三件全绿。
