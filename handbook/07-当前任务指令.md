## 二十三、下一轮（10-21）：**W19 LangGraph 状态机重写 + 记忆**

> **`ROADMAP` W19 = LangGraph 状态机、记忆（短期/长期）。** 验收标准：**能讲清状态图和手写循环的差别**。
> **本阶段规则（`handbook/04`）**：**框架样板代码主动给标准骨架，不要求逐行手写**；讲回重心 = **状态怎么在节点间流动、工具契约怎么定、循环何时终止、失败怎么兜底**。

### 第 0 件（**约 40 分钟**）：先讲清「框架替我做了什么」

**不动代码，先讲后做。** 拿 W18 的 `react_loop.py`（90 行）和 LangGraph 版并排放，逐项对照：

| W18 你手写的 | LangGraph 里是什么 |
|---|---|
| `while step < MAX_STEPS and not done` | `graph` 的边 + `recursion_limit` |
| `if reason == "stop": break` | 条件边 `should_continue` |
| `messages.append(...)` | `add_messages` reducer |
| `fail_counts` + `>= MAX_RETRIES` | 需自己写（**框架不管业务重试**） |
| `try/except → content = f"ERROR ..."` | `ToolNode` 默认容错（**要核实默认行为**） |

**讲回验收**：能指出**至少 2 个「框架替你省掉的代码」和 1 个「框架不管、还得你自己写」**。答不出就先别进第 1 件。

### 第 1 件（**约 1.5–2h，主件**）：用 LangGraph 重写 W18 循环

**先给可跑骨架**（框架样板不要求手写，但**状态定义和条件边要自己写**）。

**必须做到 5 条**：

1. **`State` 用 `TypedDict` + `add_messages`** —— 消息要能自动追加，不是每轮手动 `append`
2. **两个节点**：`agent`（调模型）/ `tools`（执行工具），**条件边**决定走哪条
3. **终止靠条件边**：模型不再要工具 → `END`；**同时设 `recursion_limit`**（如 10），超了要能看到明确报错
4. **坏 JSON 不再崩**：这是 W18 明确留下的缺口（`react_loop.py:54` `json.loads` 在 `try` 外）。**LangGraph 版必须实测坏 JSON 不崩**，手段不限（`ToolNode` 自带 / 自己包 try）
5. **同一个多步任务跑通**：`12×8 再除以 4` → 必须看到 `multiply` 后 `divide`，结果 24

**不做**：长期记忆（第 2 件）、接 RAG（W20）、多智能体、async。

**验收**：① 同任务实跑通并打印节点流转；② **坏 JSON 实测不崩**（贴输出）；③ 能讲清「`recursion_limit` 和 W18 的 `MAX_STEPS` 是不是一回事」；④ 静态三件全绿。

### 第 2 件（**约 1–1.5h**）：短期记忆

**目标**：让 Agent **记得上一轮说过什么**。

**必须做到 3 条**：

1. **同一个 `thread_id` 内两轮对话**：第 1 轮「我叫小林」，第 2 轮「我叫什么」→ 能答出
2. **不同 `thread_id` 互不干扰**：换个 id 问同样问题 → 答不出来
3. 能讲清 **`checkpointer` 存的是什么、存在哪**（内存 `MemorySaver` 就够，不接数据库）

**边界**：长期记忆/偏好存储**本轮不做**（`ROADMAP` 写了「短期/长期」，长期留到 W20 或项目③收尾时按需补）。
