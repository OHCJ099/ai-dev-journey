## 验证对象与分工

- 学员串联代码：`demo_w13.py`，上传 → 限定来源查询 → 覆盖更新 → 删除 → 再查询。
- 教练提供的验收脚手架：`archive/w13_verify.py`。脚手架与输出不算学员独立编写的业务代码或能力证据。
- 两份报销制度样张：`修订前/差旅报销制度.md`、`修订后/差旅报销制度.md`；同名来源覆盖，不修改源文件。
- 保留来源：`信息安全制度.md`。
- 只使用 `demo_w13.INDEX_PATH` 指定的 scratch 练习索引，不写 `data/` 正式语料。

## 复跑命令（PowerShell 7）

```powershell
Set-Location D:\devi-dev-journey
uv run python projects/rag-kb/archive/w13_verify.py e2e
uv run python projects/rag-kb/archive/w13_verify.py read
```

第一条验证命令会运行学员 `main()`，因此在开头清理专用练习索引并重建演示初始状态；第二条启动另一个进程，只打开同一个库并检索，不运行 `main()`、不清索引、不重新入库。不能在两条命令之间再运行演示或写库。

`e2e` 同时验证空文件、未知扩展名的拒绝行为：以已有数据的练习库为基准，比较前后 count、ID、正文、来源元数据，并用“禁止计算向量”的函数确认坏输入在向量计算前被拦住。若坏输入意外进入向量计算或被接受，脚手架会报错，不会打印通过。

## 逐项证据（按当前任务指令的验收表）

| 验收标准 | 怎么证明 | 本轮实际证据 |
|---|---|---|
| 上传新文档后能被检索到 | 包装学员 `main()` 内实际调用的 `query_index`，核验限定来源与返回条数 | 上传后差旅报销 3 条、信息安全 1 条；与来源对应 |
| 非法或空文档不污染索引 | 向已有数据的库调用 `ingest_file`，捕获预期 `ValueError`，比较完整数据快照 | 空文件与未知格式均被拒绝；count 1 → 1，ID/正文/来源不变，未进入向量计算 |
| 删除后不再召回，其他来源保持 | 核验学员删除返回值、删除后的实际检索结果与保留来源快照 | 删除返回 1；报销 0 条、信息安全 1 条；信息安全 ID/正文不变 |
| 重启不复活 | 另起独立进程执行 `read`，只打开同一个索引再检索 | 报销 0 条、信息安全 1 条，总 count 1；保留正文匹配样张 |

覆盖更新的补充证据：更新前报销 3 块；更新后只剩 `差旅报销制度.md-1`，正文逐块匹配修订版，旧尾块消失。信息安全制度的 ID/正文在更新与删除后均保持。
