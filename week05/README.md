# prompt_lab · 提示词，温度参数对比与json.loads

运行：`uv run python week05/prompt_lab.py` 这是个 prompt 实验脚本：同一个问题，用角色设定 / 少样本 / JSON 约束 / 不同温度各跑一遍，把结果排成表对比，用来搞清每种手法各自解决什么问题。

实测验证：

- 提示词对比 模型回答会按照提示词的提示造成回复风格的差异：

  ```
  组: A system摘要: 无 回复: # Python 中 `a+b` 报错的原因
  组: B system摘要: 你是一个严格的代码审查员，只指 回复: 问题：**类型不兼容**。`a` 是 `int`（整数 
  组: C system摘要: 你是一个鼓励型编程导师，先肯定 回复: # 很好的问题！ 👍

- 样本对比 模型回答会按照提示词的样本和要求约束，明确的格式要求已经能定住大结构；示例的作用是让字段名、值的写法这种细节也统一：

  ```
  组: 少样本-0 system摘要: 请你以以下的格式输出：[时间] 回复: [今天]: [学校路途中]: [小王]: [煎饼果子老板]:
  组: 少样本-1 system摘要: 请你以以下的格式输出：[时间] 回复: [时间]: 今早 [地点]: 去学校的路途中 [受害者]: 
  组: 少样本-2 system摘要: 请你以以下的格式输出：[时间] 回复: [时间]: 今早 [地点]: 去学校的路途中 [受害者]: 
  组: JSON提取 system摘要: 把用户提供的信息整理成 JSON 回复: {"字段A":"小王","字段B":"煎饼果子","字段C"
  ```

功能：提示词优化、模型样本数量对比、JSON提取、温度参数调优

技术栈：`openai` SDK 调中转端点 `tokenrhythm.studio/v1`，模型 `deepseek-flash`；key 从 `.env` 读

踩的坑：

1. 现象：变量只在 `try` 里赋值 → 解析失败时它根本不存在，兜底等于没兜（要用 `else`）
   原因：根本原因是对try except的不熟悉，把try 代码包住后却把代码执行放在了except中print导致逻辑变成了“如果报错就执行报错的目标”导致无法正常运行，兜底兜的是运行可能会报错的代码
   修法：如果报错应该打印报错之前将要被执行的内容，把没报错的代码块放进else中执行即可
2. 现象：摘要取「前 30 字」截到的全是模型复述问题，看不出差异 → 要取中段
   原因：模型回复的前30字都是趋近于接近的，回答风格高度一致
   修法：将取值调整为中间段[100:130]
3. 现象：`ArgumentParser("聊天命令行")` —— 第一个位置参数是 `prog`，不是描述
   原因：对ArgumentParser参数不熟悉，位置参数需要一一对应，第一个参数是prog
   修法：用变量名赋值进行赋值
